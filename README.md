# Обход BIL — учёт лицея

Автономный веб-сайт для учёта **классов, учеников, классных руководителей и воспитателей** лицея (7–11 классы, параллели A/B/C, 15 классов).
Работает целиком в браузере и размещается на **GitHub Pages** — без сервера, Node.js, Docker и VPS.

- Данные хранятся в **IndexedDB** браузера (переживают перезагрузку), есть резервные копии и восстановление.
- Ежегодный **переход на новый учебный год** с предпросмотром, выпуском 11 классов в архив и отменой последнего перехода; история старых лет не теряется.
- **Импорт** CSV (в т. ч. из Excel, UTF-8 / Windows-1251) и JSON, **экспорт** JSON и CSV.
- **Главная страница — «Вечерний обход»**: отметка статуса каждого ученика с временем и именем отметившего, дежурный, осталось классов. Для администратора — «Обзор дня», «Журнал», отчёты за период и **выгрузка в Excel (.xlsx)**, каждый раз новым файлом.
- **Две роли**: дежурный (USER — только обход) и администратор (ADMIN — всё остальное). Роль определяет сервер, а не флажок в браузере.
- **Google Таблицы** через бесплатный Google Apps Script (листы: Ученики, Классы, Учителя, Воспитатели, Отчёт, Архив, История, Вечерний обход).
- Адаптивный интерфейс: смартфон, планшет, ноутбук, ПК (особое внимание планшетам). Печать отчётов.
- В репозитории только вымышленные **DEMO**-данные. Настоящих людей в коде нет.

> Сайт лежит в корне репозитория; на GitHub Pages он публикуется по адресу `https://<аккаунт>.github.io/Obhod_BIL/` (см. «Публикация»).

## 2. Запуск

ES-модули не работают при открытии `index.html` двойным кликом (`file://`). Запустите любой статический сервер:

```bash
python3 -m http.server 8080        # или: npx serve .
# откройте http://localhost:8080/
```

Для проверки на GitHub-подобном подпути: `node tests/e2e/server.mjs` → `http://127.0.0.1:8765/Obhod_BIL/`.

## 3. Публикация на GitHub Pages

Сборка не нужна — сайт статический. Settings → Pages → Source: **GitHub Actions** и запустите workflow «Deploy to GitHub Pages» (Actions → Run workflow), либо Source: *Deploy from a branch* → `main` / `/ (root)`. Все пути относительные, поэтому работает и в корне, и в подпапке.

> На бесплатном тарифе GitHub Pages работает только для **публичных** репозиториев. Репозиторий содержит лишь зашифрованные данные учеников, но см. раздел 4а о рисках публичной публикации.

> Данные хранятся **в браузере пользователя** и привязаны к адресу сайта (origin). Откроете сайт с другого адреса, браузера или устройства — база будет пустой; переносите данные через резервную копию (JSON) или Google Таблицы.

## 4. Первый запуск и импорт ваших данных

1. Откройте сайт: создаётся текущий учебный год (с 1 августа начинается новый) и 15 классов (7A…11C).
2. Название лицея и год — **Настройки → Основное**. Год можно менять вручную, пока не выполнялся первый переход.
3. Загрузите данные: **Импорт и экспорт → Импортировать данные**.

### Форматы

| Формат | Как |
|---|---|
| **CSV** | Файл или вставка из Excel / Google Таблиц. Кодировки UTF-8 и Windows-1251, разделители `;` `,` табуляция определяются сами. Excel (`.xlsx`) → «Сохранить как → CSV». |
| **JSON (простой)** | `[{"fio":"Фамилия Имя Отчество","class":"7A","birthDate":"05.04.2013"}]` или `{ "students":[…], "teachers":[…], "tutors":[…] }`. Примеры — `data/example-*.json/csv`. |
| **JSON (полная копия)** | Файл, выгруженный кнопкой «Экспортировать всё». Заменяет **все** данные (с подтверждением и автоматической копией перед заменой). |

**Колонки учеников:** `Фамилия`, `Имя`, `Отчество` (или одна колонка `ФИО`), `Класс` (`7A`, `7 А`, `7-a`), `Дата рождения` (`05.04.2013`, `2013-04-05`, дата Excel), `Примечание`.
**Колонки персонала:** `ФИО`, `Должность` (*Классный руководитель* / *Воспитатель*), `Класс`, `Телефон`, `Email`.

Заголовки распознаются на русском и английском; сопоставление колонок можно поправить вручную. Перед записью показывается **пробный прогон**: сколько строк будет создано / обновлено / пропущено и какие содержат ошибки (их можно скачать CSV). Дубликаты (ФИО + дата рождения, без учёта регистра и ё/е) по умолчанию пропускаются; можно выбрать «обновить» или «создать ещё». Перед каждым импортом автоматически создаётся резервная копия.

Буквы классов — латиница **A, B, C**; кириллические А, В, С в файле заменяются на латинские автоматически (`7А` → `7A`, `10В` → `10B`).

Чтобы убрать демонстрационные данные: **Настройки → Удалить DEMO-данные**.

## 4а. Реальные данные лицея (зашифрованы)

Список учеников из исходных таблиц лежит в репозитории **только в зашифрованном виде**: `data/lyceum-data.enc.json` (AES-256-GCM, ключ из пароля через PBKDF2-SHA256, 600 000 итераций). Открытого текста в коде, в истории git и в собранном сайте нет; пароль в репозиторий не попадает.

- Загрузка: на пустой «Главной» — «Загрузить данные лицея (зашифрованные)» (или «Импорт и экспорт» → «Загрузить зашифрованные данные лицея») → ввести пароль → обычный предпросмотр импорта → «Импортировать». Расшифровка идёт в вашем браузере, на сервер ничего не отправляется.
- В набор включены **только** ФИО и класс. Даты рождения, ИИН, номера свидетельств, адреса, телефоны и данные родителей из таблиц **намеренно не переносились**.
- Классные руководители и воспитатели в таблицах не указаны (поле «Сынып жетекшісі» пустое) — добавьте их в разделе «Персонал» или импортом.
- Обновить файл: `LYCEUM_PASS='новый-пароль' node tools/encrypt-data.mjs данные.json data/lyceum-data.enc.json` (проверка: ключ `--check`). Формат входного JSON — как в `data/example-import.json`.
- Исходные `.xlsx` и расшифрованные `.json` в репозиторий не коммитить (в `.gitignore` уже добавлены).

> **Важно.** Файл в публичном репозитории доступен всем; безопасность держится на пароле. Используйте длинный случайный пароль (не меньше ~100 бит, как сгенерированный) и не передавайте его в мессенджерах. Если пароль станет известен — зашифрованный файл в истории git расшифровать смогут навсегда, поэтому в таком случае перезапишите историю репозитория или сделайте репозиторий приватным. Самый надёжный вариант — не хранить файл в репозитории вовсе, а загружать его с диска через «Импорт и экспорт».

## 4б. Допуск посетителей («кого впустить, кого нет»)

Если в `js/config.js` указан адрес Google Apps Script (`ACCESS_ENDPOINT`), сайт при открытии показывает только форму **«Вход по разрешению»**: посетитель вводит имя и сообщение, владелец получает **письмо** и решает в разделе **«Доступ»** (разрешить / отклонить / отозвать / удалить запись; в меню виден счётчик новых запросов). Владелец входит по токену скрипта («Вход для владельца»), один раз на браузер.

- Данные запроса: только то, что ввёл посетитель, и случайный секрет его браузера (на сервер уходит хэш). IP и отпечаток браузера не собираются.
- При отзыве доступа данные, сохранённые в браузере этого человека, стираются при следующем открытии сайта.
- Без связи с сервером допуска сайт остаётся закрытым.
- Лимиты: 20 новых запросов в час, имя ≤ 80, сообщение ≤ 300 символов.
- Настройка — `google-apps-script/index.html`, раздел «Допуск посетителей».

> **Честное ограничение.** Сайт — публичные статические файлы. Допуск управляет тем, кто видит интерфейс, но не может отнять данные, которые человек уже загрузил. Реальную защиту даёт **шифрование**: файл данных расшифровывается только паролем, который вы сообщаете людям сами; скрипт Google его не хранит и не выдаёт.

## 4в. Общая база: у всех допущенных одни и те же данные

При включённом допуске (`ACCESS_ENDPOINT`) все допущенные устройства работают с **одной общей базой**. Она хранится в вашей Google Таблице (скрытый лист `_Резерв` + номер версии), а Apps Script — единственный «сервер».

- **Правка одного видна остальным за несколько секунд.** Сайт отправляет изменения сразу после действия (пауза ≈ 0,25 с, серия правок уходит одним запросом) и раз в 5 с (в фоновой вкладке — раз в 30 с) спрашивает, не изменилось ли что-то у других. Окно или поле формы, в которых вы сейчас печатаете, не перерисовываются: обновление ждёт, пока вы закончите.
- **Первое подключение.** Новое устройство забирает общую базу целиком. Если у него уже были свои данные, они сохраняются в «Резервных копиях» (причина `before-live`), а общая база берётся с сервера. Если общая база ещё пуста, первое устройство с данными становится её основой.
- **Без связи** правки не теряются: они лежат в очереди (в той же IndexedDB-транзакции, что и данные), переживают перезапуск и уходят, когда связь вернётся. В шапке видно состояние: «актуально», «отправка…», «нет связи».
- **Конфликты** решаются по записям: при одновременной правке одной записи побеждает последняя отправка. Смена учебного года защищена: если два человека одновременно нажали «Начать новый год», выполнится только первый, второй получит сообщение, а его экран обновится.
- **Отзыв доступа** действует сразу: устройство получает отказ, перезагружается и стирает локальные данные.
- **Откат от случайного удаления.** Перед массовым удалением или заменой (очистка, восстановление из файла, удаление ≥ 10 записей одним действием) сервер сохраняет предыдущую версию в скрытом листе `_Откат`. Владелец возвращает её из меню таблицы: **Учёт лицея → Откатить последнее массовое изменение**.
- **Читаемые листы** («Ученики», «Классы», «Отчёт» …) обновляет тот, кто внёс изменение, через ~20 с после правки.
- Права зависят от роли (раздел 4м): дежурный отмечает обход, администратор правит данные. Журнал действий (кто, что и когда) пишется в скрытый лист `_Аудит`, история синхронизаций — в `_Журнал`.
- Данные в Google Таблице лежат **открытым текстом** (ФИО и класс); не открывайте таблицу посторонним.

> **Обновление скрипта.** Общая база требует новой версии `Code.gs`: вставьте файл в проект Apps Script, сохраните и сделайте **Развёртывание → Управление развёртываниями → ✏ → Версия: Новая версия → Развернуть** (адрес `/exec` не меняется). Пока скрипт старый, сайт работает локально и показывает «Общая база: ошибка (Скрипт Google устарел…)».

## 4г. Обход (главная страница)

После входа открывается **«Вечерний обход»**: сверху вид проверки (**Вечер / Утро / Доп.**), дата, текущее время, «Дежурный: …» (назначается в «Календаре»), счётчики «Осталось классов», «Отмечено», «Нет на месте». Ниже — поиск по всем классам, фильтр «Все / Не отмечены / Отсутствуют» и классы-«гармошки». В заголовке класса: кабинет, воспитатель, классный руководитель, `отмечено/всего`.

- У каждого ученика четыре кнопки: **Болеет / С дома / Нет (Отсутствует) / Ночует**. Касание ставит отметку, повторное касание того же статуса снимает её. «Ночует» — на месте (зелёный), остальные — нет на месте.
- Рядом с именем видно **время и кто отметил** (`21:05 · Анна П.`). Имя ставит **сервер** по допущенному устройству; поставить чужое имя нельзя.
- Красный статус сразу открывает окно **причины** (готовые варианты или своя строка); «Без причины» закрывает окно.
- Подтверждения: массовая отметка «Всем неотмеченным: Ночует» и изменение **чужой** отметки спрашивают подтверждение.
- **«Заполнить как вчера»**: неотмеченным ученикам ставится тот же статус (и причина) из обхода за предыдущий день того же вида проверки. Перед записью показывается, сколько учеников и какие статусы; уже отмеченные не меняются. Кнопка неактивна, если копировать нечего. **Для каждого класса отдельно:** рядом с названием класса есть кнопка «Как вчера» — она заполняет только этот класс (видна, пока в классе есть кому копировать).
- Класс становится зелёным и сворачивается, когда отмечен каждый ученик.
- Отметки общие (раздел 4в): другие устройства получают их за несколько секунд; без связи они ждут в очереди.
- Дата — сегодня; исправить можно два предыдущих дня. Окно хранения на устройствах: вечер — 3 дня, утро и «Доп.» — 2 дня. **Вся история** остаётся на сервере в скрытых листах `_Отметки ГГГГ`.
- Экран рассчитан на телефон: кнопки не меньше 48 px, одна колонка, сводка липнет к верху, прокрутка не прыгает.
- Названия статусов, виды проверки и сроки — в `js/domain/rounds.js`.

## 4н. Телефон

- Шапка на телефоне — одна строка (меню, учебный год, точка состояния базы, лупа, тема); поиск раскрывается по лупе и сам закрывается при переходе.
- Обход: переключатель вида, дата с кнопками «‹ ›» (листание дней без календаря браузера), часы, дежурный, сводка с лентой статусов, поиск и «Как вчера» в одной строке. Сводка закреплена вверху, кнопки — не меньше 48 px, уведомления показываются сверху, чтобы не закрывать нижнюю кнопку «Всем неотмеченным».
- «Обзор дня» показывает классы списком (класс, отмечено, у кого не в порядке), «Журнал» и «Календарь» — компактными строками вместо широких таблиц.
- Сайт можно добавить на главный экран (манифест `manifest.webmanifest`, значки в `assets/`): откроется как приложение без адресной строки. Оффлайн-режима нет — данные берутся из браузера и общей базы.
- Учтены вырезы экрана (safe-area), поля ввода 16 px (iOS не приближает страницу при вводе), ширины 320–412 px без горизонтальной прокрутки.
- **Защита от бесконечного обновления.** Если сайт сам перезагрузился 3 раза за минуту (например, из-за устаревшего скрипта Google или смены роли), автообновление останавливается и показывается объяснение с кнопкой «Попробовать ещё раз».

## 4м. Роли, обзор дня, журнал, календарь, отчёты и Excel

**Роли** (определяются на сервере `Code.gs`, проверяются на каждый запрос):

| | Дежурный (USER) | Администратор (ADMIN) |
|---|---|---|
| Обход: отметки, причины, смена статусов | да | да |
| Какие разделы видны | только «Обход» | всё меню |
| Личные данные (даты рождения, заметки, контакты) | сервер их **не отдаёт** | да |
| Запросы доступа (принять / отклонить / отозвать) | нет | да |
| Обзор дня, журнал, отчёты, выгрузка в Excel | нет | да |
| Правка учеников, классов, персонала, календаря | нет | да |
| Выдать роль администратора, очистка, массовое удаление | нет | только владелец (по токену) |

Новый человек отправляет запрос (имя, email, нужная роль) → администратору приходит письмо → в разделе **«Запросы доступа»** кнопки **«Принять»** / **«Отклонить»**. Пока решения нет, сервер не отдаёт данных. Администратора может назначить только владелец.

**Обзор дня** (`#/admin`): дата и вид проверки, по каждому классу — учеников, отмечено, на месте, болеет, с дома, нет, время и автор последней отметки; список учеников с фильтрами (класс, статус, ответственный, имя); история действий за день; кнопка **«Скачать день (.xlsx)»**. Дни старше окна хранения берутся из истории на сервере.

**Журнал** (`#/admin/logs`): вход, неудачная попытка входа, запрос доступа, принято / отклонено / отозвано, смена роли, отметки обхода, **смена статуса** (было → стало), выгрузки, правки данных, очистка, переход на новый год. Фильтры: период, группа событий, участник, объект; «Показать ещё». Запись делает только скрипт; повторные входы с одного устройства пишутся не чаще раза в 6 часов, чтобы журнал не засорялся.

**Календарь** (`#/admin/calendar`): выходные дни и дежурные по датам. Выходные не входят в отчёты; дежурный виден на экране обхода. Кабинет класса — в карточке класса.

**Отчёты обхода** (`#/admin/reports`): за сегодня, 7 дней, 30 дней, этот месяц или свой период (до 400 дней); по школе или по классу; вид проверки; график «кого не было на ночёвке» по дням, таблицы по дням, классам и ученикам.

**Excel.** Каждая выгрузка создаёт **новый** файл `evening-round-ГГГГ-ММ-ДД-ЧЧ-ММ.xlsx` (утро — `morning-check-…`, «Доп.» — `extra-check-…`; два файла в одну минуту получают `-2`). Столбцы: Дата, Время, Ученик, Класс, Статус, Причина, Ответственный. Заголовки, закрепление шапки, автофильтр, настоящие даты и время, подобранная ширина. Файл собирается в браузере без внешних библиотек (`js/domain/xlsx.js`), открывается в Excel, LibreOffice и Google Таблицах. Каждая выгрузка пишется в журнал (кто, период, число строк).

**Развёртывание Code.gs.** Эти возможности требуют новой версии `Code.gs`: вставьте файл, сохраните, затем *Развернуть → Управление развёртываниями → ✏ → Новая версия*. Часовой пояс проекта — `Asia/Aqtobe` (указан в `appsscript.json`; при ручной вставке задайте его в «Параметрах проекта»). Токен владельца и адреса почты в репозиторий не вносятся: токен выдаёт `setup()`, дополнительные адреса — свойство скрипта `ADMIN_EMAILS`.

## 4е. Анимации и подпись разработчика

- **Анимации** (`css/animations.css`, `js/ui/anim.js`): блоки страницы появляются по очереди, числа на главной «набираются», кнопки и карточки мягко реагируют на касание и наведение, окна выезжают (на телефоне — снизу), уведомления плавно въезжают и исчезают, индикатор «Общая база» пульсирует, пока что-то ждёт отправки. В вечернем обходе полоса прогресса растёт плавно, а когда класс отмечен целиком, он «выскакивает» и зеленеет с галочкой.
- Анимации **отключаются сами**, если в системе включено «уменьшить движение», а также в автотестах (признак `navigator.webdriver`; включить — `window.__LYCEUM_ANIMATE__ = true`). Отдельный сценарий проверяет их работу.
- **Подпись разработчика** — внизу каждой страницы (в том числе на экране входа): `index.html`, блок `footer.site-foot`; в печать не попадает.

## 4ж. Тёмная тема

- **Выбор:** кнопка в шапке (◐ → ☀ → ☾ по кругу) или **Настройки → Оформление**: «Как в системе», «Светлая», «Тёмная». «Как в системе» следует настройке телефона или компьютера, в том числе когда она меняется на лету (вечером).
- Выбор запоминается в браузере (`localStorage`, ключ `lyceum-theme`) и применяется **до первой отрисовки** (`js/theme-init.js`), поэтому страница не мигает светлым; смена темы идёт плавным переходом цветов, окрашиваются также цвет адресной строки браузера и графики.
- Палитра — переменные в `css/dark.css`; контраст основного текста, кнопок, меню и подсказок проверен автотестом (не ниже 4,5:1, WCAG AA). Печать всегда светлая.

Оформление переработано как у рабочей внутренней системы: спокойная серо-синяя основа, цвет — только у действий, статусов, предупреждений и активного состояния; рамки и карточки — только там, где они что-то группируют.

У каждого пункта иконка; активный раздел отмечен полоской. ## 4л. Скорость

Замеры показали: сам сайт быстрый (переходы 0,1–0,6 с даже при замедлении процессора в 4 раза), а **скрипт Google отвечает за 4,5–35 с** (канал до GitHub — 0,2 с). Раньше каждое открытие сайта ждало этот ответ, чтобы проверить доступ. Полная анимация загрузки — раз в сутки, потом короткая. Изменения других людей по-прежнему доходят за время ответа скрипта Google (секунды) — это предел Apps Script.

## 5. Ежегодный переход на новый учебный год

**Новый учебный год → «Начать новый учебный год»**:

1. Показаны текущий и новый год.
2. Предварительный отчёт: `7A — 28 учеников → 8A … 11A — 27 учеников → выпуск`.
3. **Выпуск 11 классов**: «Архивировать выпуск» (по умолчанию: статус «Выпускник», в архив; ничего не удаляется) или «Оставить в текущем году» (ученики ждут оформления выпуска; позже кнопка «Оформить выпуск» на главной). Отмена — кнопкой «Отменить».
4. Руководители переходят вместе с классом (7A → 8A) или остаются за буквой класса; отдельных учеников можно оставить на второй год.
5. Резервная копия создаётся автоматически; можно скачать файл.
6. Для подтверждения введите новый учебный год (`2027–2028`) → «Подтвердить переход».
7. Операция атомарна (одна транзакция IndexedDB), защищена от двойного запуска (в т. ч. из второй вкладки). Классы 7-й параллели нового набора создаются пустыми. Если подключены Google Таблицы, данные отправляются автоматически.

Старый год остаётся в **Истории** только для просмотра (классы, ученики, руководители, числа на тот момент). **Отмена последнего перехода** доступна на той же странице: нового года не будет, выпускники вернутся в 11 классы. Изменения, внесённые в новом году после перехода, при отмене теряются (об этом предупреждает окно подтверждения).

## 6. Подключение Google Таблиц

Подробная инструкция с кодом — `google-apps-script/index.html` (на сайте: **Настройки → Google Таблицы → Пошаговая инструкция**). Кратко:

1. Создайте Google Таблицу → *Расширения → Apps Script*.
2. Вставьте содержимое `google-apps-script/Code.gs`, сохраните.
3. Запустите функцию `setup()` (разрешите доступ) — она покажет **токен** и создаст ежедневный триггер.
4. *Развернуть → Новое развёртывание → Веб-приложение*: «Выполнять как» — *Я*, «Доступ» — *Все*. Скопируйте URL (`…/exec`).
5. На сайте: **Настройки → Google Таблицы**: URL и токен → «Сохранить».
6. «Проверить соединение» → «Выгрузить в Google Таблицы».

**Как устроено ежедневное обновление (режим без общей базы).** Источник данных — браузер; таблица — копия. При включённой автосинхронизации сайт отправляет данные через несколько секунд после открытия, при возврате на вкладку и раз в час (если есть несинхронизированные изменения или прошли сутки), а также после перехода на новый год. Триггер Apps Script раз в сутки проверяет «свежесть» и пишет письмо-напоминание, если данных нет более 26 часов (сервер не может сам забрать данные из браузера).

## 7. Резервные копии и восстановление

- **Настройки → Резервные копии**: автоматические копии в браузере (последние 10) перед переходом, импортом, восстановлением, очисткой; ручная копия; скачивание JSON; восстановление из файла или из копии.
- В файл копии **не попадает токен** Google.
- Safari/iOS может удалять данные сайтов, которыми не пользовались ~7 дней: периодически скачивайте JSON и/или включите Google-синхронизацию с резервной копией. Сайт запрашивает у браузера «постоянное хранение» (Настройки → Хранилище).

## 8. Модель данных (кратко)

Класс, зачисление ученика и назначение руководителя **принадлежат учебному году**: `classes` (`2026-2027:7A`), `enrollments` (`год:ученик` → класс, статус, переводы), `assignments` (`класс:роль` → сотрудник). Ученики и сотрудники — отдельные записи без привязки к году. Поэтому «состояние на год X» — просто выборка по `yearId`, а переход создаёт записи нового года, не меняя прошлые. Журнал `promotions` хранит данные для отмены.

E2E проверяет: добавление/правку/удаление/перевод учеников, поиск, назначение персонала, переходы 7→8…10→11 и выпуск, историю, отмену перехода, отчёты, импорт (CSV 1251, TSV, JSON), экспорт, очистку и восстановление, запрос к Google Apps Script (структура JSON, ошибки, автосинхронизация), адаптивность (375, 768, 1024, 1440), режим без IndexedDB, две вкладки, печать. Любая ошибка в консоли браузера роняет сценарий.

## 10. Известные ограничения

- **Общая база требует связи для обмена.** Без допуска (`ACCESS_ENDPOINT` пуст) данные живут в одном браузере, а Google Таблица — односторонняя копия. С допуском данные общие (раздел 4в), но каждое устройство хранит и локальную копию; одновременная правка одной записи разрешается «побеждает последняя». Лимиты Apps Script (квоты запросов, задержка 1–3 с) рассчитаны на десятки людей, не на сотни.
- **Что роль дежурного не скрывает.** Дежурный получает имена и классы всех учеников (иначе нечего отмечать), но не даты рождения, заметки и контакты. Разделить видимость по классам пока нельзя.
- **Скорость сервера.** Apps Script отвечает от 4 до 35 секунд; отметки не ждут ответа (очередь), но «Журнал», «Отчёты» и дни старше окна хранения загружаются с задержкой.
- **Журнал можно править руками**, если у человека есть редакторский доступ к самой Google Таблице: держите таблицу приватной. Из сайта журнал стереть нельзя.
- Выгрузка за период содержит только сделанные отметки (дни, когда обход не проводился, в файле не появятся); выгрузка «дня» содержит всех учеников, неотмеченные — со статусом «Не отмечен».
- Старые открытые вкладки до ~10 минут могут работать по прежним правилам (до обновления страницы).
- Импорт: Excel `.xlsx` напрямую не читается — только CSV (Файл → Сохранить как). Выгрузка обхода — в `.xlsx`.
- Буквы классов — A/B/C (кириллические А/В/С приводятся к латинице; «Б» не поддерживается).
- Правка прошлых учебных годов запрещена (только просмотр); ученик, отчисленный внутри года, в «Истории» этого года не показывается.
- Ежедневное обновление Google Таблиц — «по открытию сайта» (см. п. 6): если сайт не открывать, данные не отправляются.
- Safari/iOS может очищать хранилище неиспользуемых сайтов; делайте резервные копии.
- В Google Таблице на листах находятся персональные данные: держите её приватной.
